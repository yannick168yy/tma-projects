# BetoGo 人工 UAT 清单

本文档用于测试环境人工验收。自动化脚本已覆盖基础页面可达性和 mock 数据冒烟；本清单聚焦真实设备、真实三方链路、图片/相机、游戏加载和视觉体验。

## 1. 测试范围

| 模块 | 验收目标 | 是否必须人工 |
|------|----------|--------------|
| Telegram Mini App 真机 | TG 内打开、自动登录、支付弹窗、返回行为、设备兼容 | 是 |
| 三方支付沙箱 | Telegram Bot Payments / Ammer Pay 沙箱支付、Webhook 入账、订单状态 | 是 |
| KYC 图片/相机 | 手机相机权限、证件上传、活体/自拍、后台审核 | 是 |
| SG 游戏加载 | 真 SG 游戏 iframe/跳转、余额扣减、回调结算、退出后余额刷新 | 是 |
| 视觉验收 | 移动端布局、图片清晰度、遮挡、暗色主题、语言文案 | 是 |
| 后台管理 | 管理员登录、用户、提款、KYC、游戏、活动、支付渠道 | 部分人工 |
| 基础页面冒烟 | 前后台页面可打开、登录态 mock、核心页面文案 | 可脚本 |

自动化入口：

```bash
node scripts/e2e-smoke.mjs
```

## 4. UAT 执行清单

### 4.1 Telegram 真机打开与登录

| 步骤 | 操作 | 期望结果 |
|------|------|----------|
| 1 | 在手机 Telegram 打开测试 Bot 的 Mini App | 应进入 BetoGo 启动页并完成加载 |
| 2 | 使用 `UAT-TG-A` 首次打开 | 自动创建或恢复平台用户 |
| 3 | 查看首页顶部余额和登录状态 | 显示真实用户状态，不出现 mock 数据 |
| 4 | 关闭 Telegram 后重新打开 Mini App | session 可恢复，用户不应重复注册 |

| 步骤 | 操作 | 期望结果 |

## 7. 退出准则

UAT 通过需同时满足：

1. P0 主流程全部 `PASS`：Telegram 登录、充值、KYC、游戏、提款、后台审批。
2. 三方链路没有未解释的资金不一致：余额、订单、ledger、后台展示一致。
3. 所有 `FAIL` 已修复并回归。
4. `WARN` 已确认不阻断当前测试环境验收。
5. 至少一台 iPhone、一台 Android、一台桌面后台完成视觉验收。
6. 第 3 阶段 E2E 冒烟脚本仍可通过。
