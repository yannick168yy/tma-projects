# 包网后台使用手册

版本：2026-09-06。适用于当前仓库的「平台控制台」和租户业务后台。

本手册根据现有页面及服务端权限编写，未以本次编写作为线上验收。菜单和功能以实际部署版本为准；尚未完成的能力见第 12 节。

## 1. 入口与账号

平台控制台供包网平台工作人员管理所有客户站；租户业务后台供客户管理自己的玩家、活动、充提及账单。两者账号体系独立。

- 测试环境平台入口：`https://www.188facai.com/platform/`（按仓库部署配置）。
- 租户业务后台：使用开站结果中返回的 `https://<后台域名>/admin-panel/`，不要用其他租户域名登录。
- 生产入口由运维提供，本手册不假设生产已部署相同版本。
- 平台账号由平台负责人提供；租户初始超管账号在「一键开站」时设置。手册不提供默认密码。

平台角色权限：

- **平台超管**：开站、域名、品牌、文案、通道、App 参数、功能开关、套餐区间、代登录，以及财务和运营操作。
- **平台运营**：可变更租户状态、管理活动模板及风控联防；财务写入和超管专属设置不开放。
- **平台财务**：可维护分成方案、额度、账单和财务队列；不能代替超管开站或修改品牌等配置。

页面出现按钮不等于账号具备权限，服务端仍会校验。提示 403 时先确认当前账号角色。

## 2. 新客户开站：从准备到交付

### 2.1 开站前准备

准备运营商名称、租户代号、套餐、市场、前台域名和后台管理员账号；同时确认品牌素材、支付安排、聚合商子代理、商务计费规则。

租户代号为 3～16 位小写字母或数字，以字母开头，创建后不可改。当前开站页面开放菲律宾 PH（PHP）及印尼 ID（IDR）。一个租户可选择多个市场，每个域名需关联所选市场。

### 2.2 执行开站

1. 平台超管进入左侧「一键开站」。
2. 填写租户代号、运营商名称，选择套餐和市场。
3. 添加至少一个域名，只填写域名，不带 `https://` 或页面路径，并选择所属市场。
4. 设置租户后台超管账号和至少 10 位密码。
5. 连接池一般保留默认初始 2、最大 4；扩容由运维根据服务器容量判断。
6. 点击「开站」，等待建库、结构初始化、配置复制、登记及自检结束。

成功结果会显示数据库、建表数量、业务后台入口及自检明细。开站复制配置，不复制自营站的玩家、注单和充提数据。

若显示「已建库，但自检未全部通过」，或种子表复制行数为 `-1`，先记录租户代号和失败详情交运维处理；不要将其当作已交付，也不要反复更换代号重开。

### 2.3 交付前检查

1. 在「租户列表」进入客户详情，核对名称、代号、市场、套餐和状态。
2. 配置品牌与文案，检查域名解析和证书，实际打开前台及业务后台。
3. 配置并下发聚合商、支付通道，验证游戏启动和经授权的小额充提流程。
4. 在「计费与账单」挂分成方案，按约定录入额度和授信。
5. 在租户后台检查首页装修、活动、导航与可见功能。
6. 如需 App，配置出包参数并由出包人员制作、安装验证。
7. 交付准确的前台与后台地址、账号、套餐范围、计费约定及支持联系人。

开站自检通过不代表游戏、支付及客户自有域名均已完成外部联调。

## 3. 租户列表、状态及协助登录

从「租户列表」选择客户，详情页包含：概览、套餐与开关、品牌、文案、域名、通道与聚合商、App 出包、计费与账单。

### 状态变更

在「概览 → 状态变更」选择目标状态并确认。当前行为如下：

- **试用 / 正常**：允许站点访问、充值和提现。
- **停提现**：禁止新提现，仍允许充值。
- **停充值**：禁止新充值，仍允许提现；它不是同时停止充提。
- **停站**：阻止前台业务访问，租户后台仍保留账单等处理入口。
- **关站**：当前页面没有恢复操作；不要用关站代替临时停站。关站也不代表已完成数据导出、清库或合同退出。

自营站不能通过此页面变更状态。可选目标受当前状态限制。变更会影响该客户玩家，操作前核对租户代号。

### 以租户身份登录

平台超管在租户详情右上角点击「以租户身份登录」，确认后会在新标签打开该租户业务后台。代登录会留痕，客户可在自己的操作日志中看到。

若没有打开新标签，检查浏览器是否拦截弹窗。已关站租户不能使用该按钮。操作时再次核对客户身份，结束后退出租户后台。

## 4. 套餐、功能开关与品牌定制

### 4.1 功能套餐与分成方案是两类设置

功能套餐决定可用能力及客户可调整的参数范围；分成方案决定向客户如何计费。开站时选了套餐，仍需另行挂分成方案。

「套餐管理」当前用于维护所选套餐的配置允许区间：填写下限、上限并保存；两端均留空表示清除该项限制。修改影响挂该套餐的所有租户。未登记限制的配置项不会由此区间机制拦截。该页不是完整的套餐新增或默认开关编辑器。

「租户详情 → 套餐与开关」支持逐项选择：

- 跟随套餐：使用套餐默认值。
- 单独开：为当前租户启用。
- 单独关：为当前租户停用。

选择后保存生效，以最右侧「生效」列核对结果。客户自助修改活动参数时，超出套餐允许区间会被拒绝。彩票及棋牌的后端过滤限制见第 12 节。

### 4.2 品牌

进入「租户详情 → 品牌」：

1. 填写站名、短名、文字 logo 前后段及标语。
2. 按需设置主色、文字色、强调色、圆角和字体；主题字段留空使用默认值。
3. 点击「保存」。
4. 上传亮色底 logo、暗色底 logo、Favicon、App 图标。支持 PNG、JPEG、WebP，单图不超过 2MB；上传成功会保存对应配置。
5. 打开客户前台刷新，检查标题、logo、颜色及图片显示。

没有图片时可先使用文字 logo。Web 品牌设置更新无需重新构建前端；原生 App 内已打包的资源变更仍需重新出包验证。

### 4.3 文案

进入「租户详情 → 文案」，选择语言，搜索词条，查看平台默认文案后填写租户文案并保存。

`{{brandName}}` 等变量必须原样保留。修改后在前台切到对应语言检查实际页面。删除覆盖会回落到平台默认文案。若词条目录加载失败，联系运维修复文案目录，不要任意编造 key。

## 5. 域名与证书

在「租户详情 → 域名」添加平台子域名或客户自带域名，并选择市场和用途。平台子域名由系统生成；客户自带域名需由域名管理方完成解析，后台域名也需解析。

1. 添加域名后点击「巡检 DNS/证书」。
2. 查看状态：未探测、待解析、已签发、即将到期、异常。
3. 将鼠标放到状态上查看具体原因，核对到期日期。
4. 客户自带域名如由本平台负责证书，可启用「自动签发」；页面提示下一轮最多约 1 小时处理，依赖运维已配置签发任务。
5. 使用外部证书托管时，与运维确认后关闭平台自动签发。
6. 实际打开 HTTPS 前台和后台确认可访问，再交付客户。

删除域名会移除平台登记，不会替客户修改 DNS，也不会自动修正已打包进 APK 的线路组。变更前检查 App 线路及现有入口。

## 6. 通道与聚合商

### 6.1 win568 子代理

进入「租户详情 → 通道与聚合商」的聚合商区域，填写已在上游开好的子代理账号、CompanyKey，按需填写 ServerId、状态及备注。

保存后执行「下发到租户库」。之后该租户的 win568 调用会使用所下发的子代理配置。编辑已有密钥时留空表示不改；不要把显示的掩码当作真实密钥填写。

如提示平台凭据主密钥未配置，交运维处理。成功下发后再做游戏与钱包联调。

### 6.2 支付通道

填写通道代号、归属、商户号、密钥、费率、每笔固定手续费、启用状态和排序。通道代号需与既有支付服务匹配，例如 `unispay`、`yfpay`，不能仅靠新增代号接入新支付商。

保存分配后执行下发。**没有分配到的通道会被关闭并对客户端隐藏**，下发前检查完整分配清单。

当前实际可交付模式为平台统一代收代付。界面虽提供「租户自带通道」及凭据管理，但支付调用切换和商户号回调归属尚待真实通道接入；仅保存商户号、密钥或归属不能视为模式 B 已开通。未经专项联调，不应按模式 B 向客户交付。

## 7. 分成方案与月度账单

### 7.1 建立方案

平台超管或财务进入「分成方案」，新建方案并设置月费与分成的关系：月费加分成，或两者取较大值。

可组合充值佣金、GGR 分成、流水返点和月费。按合同填写费率、范围或分档；分档可使用整体或累进方式。GGR 分成需逐项确认是否扣活动成本、团队佣金和通道手续费，以及负 GGR 结转下期还是当期归零。

费率栏以百分比填写，例如 5 表示 5%。月费栏以 USDT 填写。修改规则不会改写已生成的历史账单。

进入「租户详情 → 计费与账单」，选择「挂/换分成方案」。未挂方案不能出账。

### 7.2 月度操作顺序

1. 检查近 30 天日切快照，确认充值、流水、GGR、成本、币种及汇率。
2. 发现未锁定日期数据不完整时，由财务核查后执行重算；已锁定日期不能通过重算覆盖。
3. 在「出账」选择历史月份并点击「试算」。
4. 核对数据天数、逐项基数、费率、金额、上期结转和下期结转。缺汇率会阻止出账，先由运维补齐来源再重算。
5. 点击「生成账单」。生成会锁定该周期的日切快照。
6. 打开账单详情，按当前状态允许的操作完成开票、客户确认及核销。
7. 核销后复查额度流水和人工队列。

账单状态流程为：草稿 → 待客户确认 → 已确认 → 已核销。争议账单需处理原因后重新开票、重新确认，不能直接核销。已核销和已作废是终态，界面不提供继续变更。

「人工调整」用于记录差额，负数表示减免，必须填写原因；已确认、已核销或已作废账单不可直接调金额。历史账单不应靠修改当前分成规则来纠正。

**核销会实际扣划租户额度账户，并非仅修改账单标签。** 额度不足会记欠款并进入人工队列。

## 8. 额度、对账和欠费处理

### 8.1 额度账户

在租户「计费与账单」查看余额、授信、押金及流水。可动用额度等于余额加授信，不另外加上押金显示值。

- 「调授信」：按商务批准的额度填写新值。
- 「记一笔」：选择押金/额度充入、额度退回或人工调整，填写金额和摘要。
- 正数增加余额，负数减少余额；摘要写清款项原因及对账凭证。
- 记账本身不会从外部银行或链上自动收款，需先核实实际到账。
- 流水只增不改；记错时通过相反方向的流水冲正并写明原因。

### 8.2 平台集中查看

「平台总览」用于跨客户观察经营情况；「账单」集中筛选和处理各租户账单；「资金模式对账」按日期、租户和币种核对平台代收代付、自带通道分类及通道手续费，可展开查看通道明细。

模式分类数据不等于该模式已完成支付接入。对账异常时同时核对订单、实际资金去向和通道配置。

「额度与队列」集中查看可动用额度及待处理事项。完成实际处理后再标记已处理或驳回；队列状态操作不能替代充值、调账或账单核销。

### 8.3 欠费处理

当前代码默认按已开票且未核销账单的开票日起算：1 天进入提醒队列，3 天停提现，7 天停充值，14 天停站。实际阈值可由部署配置调整，由运维确认。

手动执行催收判定也可能直接改变客户状态，不是只刷新列表。自营站不参与自动降级。停充值仍允许提现，不能理解为累计关闭所有资金操作。

核销后系统会按剩余未核销开票账单、可动用额度及当前状态判断是否恢复。财务应再次查看租户状态；涉及人工停站原因时需与运营复核，不要仅凭付款记录认为限制已解除。

## 9. 活动模板与风控联防

### 9.1 活动模板

平台超管或运营进入「活动模板」：

1. 将来源租户的活动参数配置好。
2. 选择「从租户当前配置导出模板」，选择来源租户和需要复制的区块，填写代号、名称、适用市场及说明。
3. 套用时选择目标租户，比较「当前」与「套用后」的差异。
4. 参数校验有错误时先修正；确认覆盖范围后再套用。
5. 查看套用记录，并到目标租户后台及前台复核。

模板套用会覆盖所选活动配置，不能当作纯预览；不会复制来源租户的玩家数据。删除模板不回滚已套用客户的配置。租户侧也可使用已开放的模板。

### 9.2 风控联防

「风控联防」支持联防名单和跨租户撞库识别。平台超管或运营可管理名单；联防采用租户自身判定与平台判定中更严格的结果。

可按至少 2、3、5 家筛选跨站重复设备、手机号或收款账号。重复信号需要核实，不应直接当作违规结论。

加入名单时选择只记录、转人工复核或直接拒绝；撞库榜快捷加入默认转人工。平台只保存摘要与掩码，不提供从摘要还原玩家原值的能力。名单对全平台客户生效，修改后需考虑缓存刷新时间，不能认为只影响当前租户。

若提示联防密钥未配置，说明能力尚未启用，联系运维。

## 10. App 参数与出包交付

平台进入「租户详情 → App 出包」，按市场添加或修改参数：包名、桌面名、线路组、TG 旁路频道、启动屏底色、签名引用名和版本号。

- 发布后保持包名和签名一致；签名引用对应出包机上的签名配置，后台不保存签名文件和密码。
- 线路组只能选择已登记且启用的站点域名，按优先级排序。
- 每次更新增大 `versionCode`，同时填写面向用户的 `versionName`。
- 保存参数不会生成 APK，也不会更新已安装 App。

租户可提交出包申请，由平台出包人员在专用机器执行页面提供的出包命令，验证安装和线路后回填交付结果。当前平台「App 出包」页主要维护参数，没有完整的申请处理工作台；申请状态及下载地址回填需通过现有管理接口由技术人员处理。

## 11. 租户管理员自助操作

客户使用自己的业务后台。玩家管理、充提等基础操作参见[管理后台使用手册](ADMIN-BACKEND-GUIDE.md)，其中旧账号和部署说明不作为本次交付依据。

### 平台账单

在「系统 → 平台账单」查看分成方案、额度、账单和每日明细。租户超管或财务核对待确认账单，有异议时填写争议原因；确认后由平台执行核销。客户不能自行修改平台费率、授信或核销金额。

### 自助配置

在「系统 → 自助配置」使用支付通道、App 出包、开放 API 三个页签。入口对租户超管及财务展示，具体写操作以服务端授权为准。

- **支付通道**：仅维护已分配的自带通道商户号及密钥，不能自行更改通道归属、平台费率或新增支付商；适用第 6 节的未接通限制。
- **App 出包**：维护允许修改的桌面名、线路、版本等参数并提交申请；同一市场同时只能有一条待处理申请。包名与签名等基础配置由平台维护。
- **开放 API**：创建密钥时填写用途、最小必要权限、每分钟请求上限及可选 IP 白名单。上限可设 10～600。完整密钥仅创建时显示一次，立即妥善保存；丢失需吊销重建。

开放 API 只读，用于报表与对账，不支持通过它调余额或发起充提。吊销后旧密钥失效；401 检查密钥，403 检查权限和白名单，429 表示超频。接口及示例见[开放 API 说明](../product/OPEN-API.md)。

## 12. 当前能力边界与常见问题

本版本不应对客户承诺：

- 租户自带支付通道填写凭据即可完成收付款接入。
- 第二家聚合商可直接在后台新增并启用；目前只有 win568。
- 彩票和棋牌开关具备完整的后端游戏品类过滤；目前仍存在仅前端控制的范围。
- 点击出包申请即可自动拿到 APK。
- 关站按钮会自动完成数据退出、备份交付或删除。

常见处理方法：

- **品牌或文案没更新**：核对租户、访问域名和语言，确认保存成功后刷新客户端。
- **某功能仍可见或不可用**：核对功能生效列、套餐范围、租户状态，再检查当前版本限制。
- **域名打不开**：先看 DNS/证书巡检详情，核对后台域名是否也已解析。
- **保存凭据失败**：检查是否提示主密钥缺失或解密异常，交运维处理；不要用掩码覆盖真实密钥。
- **账单生成失败**：检查是否挂方案、周期是否正确、汇率是否齐全及是否已存在该周期账单。
- **额度充入后仍受限**：检查是否还有未核销账单、是否已完成核销及当前租户状态。
- **操作返回 403**：核对平台与租户账号是否混用、账号角色和目标域名。
