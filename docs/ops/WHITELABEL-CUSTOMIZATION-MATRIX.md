# 包网可定制范围与套餐说明（销售口径）

> 面向销售与售前。**对客户承诺以本文为准**，不以口头或截图为准。
> 运营侧怎么操作见[包网后台使用手册](WHITELABEL-ADMIN-GUIDE.md)。
>
> 写这份文档的原因：包网谈单最容易出事的不是做不到，而是**先答应了再发现做不到**。
> 所以下面第 3 节「不可定制」写在了「可定制」前面。

## 1. 三档套餐

| 套餐 | code | 覆盖范围 |
|---|---|---|
| 标准版 | `standard` | 品牌包 + 文案覆盖 + 首页装修 + 功能开关 |
| 进阶版 | `advanced` | 标准版 + 首页区块拖拽 + 活动模板市场 |
| 旗舰版 | `flagship` | 进阶版 + UI 定制 overlay + 开放 API |

套餐决定**两件事**：哪些功能默认开启，以及运营参数能调到多大范围。
套餐与分成方案是两套独立配置，谈单时不要混为一谈——分成方案见使用手册第 7 节。

### 运营参数的可调区间按套餐收紧

客户能自己调，但只能在套餐允许的区间内。超出区间后台会直接拒绝。

| 参数 | 标准版 | 进阶版 | 旗舰版 |
|---|---|---|---|
| 提现下限 `withdraw_min` | 50 – 100,000 | 20 – 200,000 | 0 – 1,000,000 |
| 提现上限 `withdraw_max` | 100 – 500,000 | 100 – 2,000,000 | 0 – 100,000,000 |
| 彩金流水倍数 `bonus_wager_mult` | 1 – 20 倍 | 0.5 – 30 倍 | 0 – 100 倍 |
| 返水比例 `rebate_rate_pct` | 0 – 1.5% | 0 – 2.5% | 0 – 5% |
| 返水封顶 `rebate_max_bonus` | 0 – 50,000 | 0 – 200,000 | 0 – 1,000,000 |

> 数值随平台策略调整，**报价前以平台后台「套餐管理」页的当前值为准**，不要背这张表。

## 2. 可定制清单

### 2.1 品牌与视觉（全套餐）
站点名、简称、Logo 文字（主色段 / 强调色段）、标语、
浅色 Logo、深色 Logo、Favicon、App 图标、主题色变量。

### 2.2 文案（全套餐）
按语言逐条覆盖前台文案，不改代码。没覆盖的条目自动回落默认文案。

### 2.3 功能开关（全套餐，共 20 个）

游戏品类：`slots` `live` `sports` `lottery` `fishing`
玩家运营：`task` `checkin` `spin` `vip` `rebate` `loss_rebate`
代理体系：`team_commission` `agent_center`
社群与增长：`community` `tg_broadcast` `app_download`
账号与服务：`kyc` `cs_ai` `login_telegram` `login_google`

> ⚠️ `lottery` **目前只在前端导航生效**：游戏库里没有对应的品类取值，接口层无从过滤。
> **不要承诺彩票品类的后端完整过滤。** 棋牌同理——它根本不是独立开关，
> `FEATURE_KEYS` 里没有这一项，谈单时不要把它当成可单独开关的品类。

### 2.4 首页装修（标准版起可显隐，进阶版起可拖拽排序）
12 个区块：`popular` `recommended` `newGames` `slots` `casino` `perya`
`fishing` `lottery` `baccarat` `highRtp` `highRebate` `sports`，
外加 banner、公告、最近在玩、活动横条、厂商专区、投注榜等运营区块。
每块可单独显隐、排序、传参（如展示数量、大图/小图版式）。

### 2.5 底部导航（进阶版起）
5 个槽位 `casino` `bonuses` `team` `games` `menu`，可改顺序、显隐、图标、跳转目标
（图标与跳转目标都限定在白名单内）。

### 2.6 域名与 App
自有域名（含多域名、多市场），证书自动签发与到期巡检；
App 出包参数（包名、图标、启动图、线路域名）可按租户配置。

### 2.7 活动模板（进阶版起）
从平台活动模板市场取用并按自家参数落地。

### 2.8 UI 定制 overlay（仅旗舰版）
以文件覆盖方式定制页面，能力最强但**每次主干发版都要回归被覆盖的文件**，
交付与维护成本显著高于前几项。发版流程见 [tenant-overlay.md](tenant-overlay.md)。

### 2.9 开放 API（仅旗舰版）
只读数据接口，自带 API Key 鉴权与按 key 限流。

## 3. 不可定制清单（谈单必须先说清）

以下四块**任何套餐都不开放定制，包括旗舰版的 overlay**：

| 领域 | 为什么锁死 |
|---|---|
| 钱包账变 | 余额、冻结、流水的写入路径。改错就是资金错账，且不可逆 |
| 注单链路 | 下注、结算、派彩。与聚合商对账口径绑定，动了就对不上账 |
| 风控引擎 | 黑名单、跨租户联防、提现闸门。按租户放宽等于给团伙留后门 |
| 结算计费 | GGR 口径、日切快照、账单生成。这是平台向客户收钱的依据，客户不能改 |

> 目前靠约定与 code review 保证，**尚无构建期强制拦截**（X-1 未做）。
> 因此这条边界的执行依赖人，接单时更要写进合同。

### 其余明确不能承诺的
- **租户自带支付通道填了凭据就能收付款**：凭据能加密存储，但支付调用尚未切到按租户凭据，
  当前所有站实际都走平台统一代收代付。客户自带通道需**逐家单独对接**。
- **第二家聚合商可在后台自助新增**：目前只有 win568。
- **点出包申请就能拿到 APK**：出包流程含人工环节。
- **关站按钮会自动完成数据导出与交付**：数据退出机制尚未建（X-2 未做），
  **保留期、交付格式、删除时点必须在合同里单独约定**。

## 4. 开站 SOP（销售侧需要提前收齐的信息）

签约后交付前，需要客户提供：

1. **站点标识**：租户代码（英文小写，将作为库名后缀，建库后不可改）、站点名、简称
2. **域名**：前台域名（可多个）、后台域名，且 **DNS 需提前解析到平台 IP**，否则证书签不下来
3. **市场与币种**：目标市场、结算币种、时区
4. **品牌素材**：Logo（浅色/深色）、Favicon、App 图标、主题色
5. **套餐与分成方案**：两者分别确认
6. **资金模式**：平台统一代收代付，还是自带通道（**自带通道要单独排期对接**）
7. **App 需求**：是否出包、包名、线路域名

运营侧的执行步骤见[使用手册第 2 节](WHITELABEL-ADMIN-GUIDE.md#2-新客户开站从准备到交付)。
