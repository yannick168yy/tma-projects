# BetoGo 客户端 v0.1 前端决策

> **状态**：已确认 · 2026-05-24

## A. 联调策略

| 项 | 决策 |
|----|------|
| 阶段 | 先搭架构 + **模块级 mock adapter**，BFF 就绪后切真实 API |
| Mock 删除 | BFF 联调通过后删除 mock 实现，保留接口类型 |

环境变量：

- `VITE_BFF_BASE_URL` — BFF 地址（默认 `http://localhost:3000/api/v1`）
- `VITE_USE_MOCK_API=true` — 开发构建启用 mock（Docker 本地默认可开）

---

## B. 认证与启动流

| 项 | 决策 |
|----|------|
| 全站维护页 | **本期不做** |
| 开屏页 | BetoGo Logo + **加载动画**；并行 initData 登录（TG）或会话恢复 |
| 非 TG 环境 | 计划接入 **Google 登录**（v0.1 仅 UI 占位）；设计统一 **LoginSheet** |
| Login 入口 | **默认入口在顶栏余额区**（未登录显示 Sign in / 余额占位） |
| Login 触发 | 点击 **任意游戏**、**个人中心**、**充提区块**（Top up / Wallet）时弹出 LoginSheet |
| TG 环境 | LoginSheet 主 CTA：Telegram 登录（initData → BFF） |
| Web 环境 | LoginSheet 展示 Google 登录按钮（待 BFF OAuth） |

## C. KYC / 个人信息

| 项 | 决策 |
|----|------|
| 入口 | **个人中心 → Personal Information**（不单独 KYC 中心页） |
| 字段 | **姓名、性别、生日**（v0.1） |
| 证件上传 | **不做** |
| 法币提现 KYC 门禁 | 依赖上述资料 + BFF `GET /kyc/status`（后端可映射为 profile 完整度） |

## D. 活动与邀请

### 保留的活动

| ID | 活动 | 规则摘要 |
|----|------|----------|
| `trial` | 试玩官 / First Play | 新人 ₱88 等（Bonuses 卡片） |
| `referral` | 老带新 Refer & Win | Copy Link；完成任务后改 **Claim** + RedPacketSheet |
| `firstdep` | 首充 | **120%**，最高 **₱1,000**；保留 |

### 首页快捷卡引导（高亮 + 旗标）

| 快捷卡 | promo | 条件满足后 |
|--------|-------|------------|
| **First Play**（原 Free Play） | `trial` | 高亮 + 旗标 → 活动页对应区；Claim 校验身份后弹层领取 |
| **Refer & Win** | `referral` | 任务完成 → 高亮 + 旗标；Share Link → **Claim** + RedPacketSheet |
| **First Dep** | `firstdep` | 首充条件满足 → 高亮 + 旗标；Deposit Now → **Claim** |

邀请多人：**列表展示**，区分 **邀请方 / 被邀请方** 角色。

### 其它

| 项 | 决策 |
|----|------|
| 分享 | **仅 Copy Link**（不用 TG Share API） |
| 记录列表 | **Bonuses + Profile 内嵌**（邀请记录、红包记录） |

## E. TG Wallet 钱包流

| 项 | 决策 |
|----|------|
| 通道 | **仅 Telegram Wallet**（v0.1） |
| 流程 | 完整：创建订单 → 调 TG → 轮询 `GET /deposits/{id}`（依赖 BFF+TG） |
| 余额展示 | **仅 PHP**；若充值 USDT，按汇率 **折算显示 PHP** |
| 提现预检 | **阻断**（KYC / 流水不足不可提交） |

1. 技术架构（api / Pinia / mock）+ 品牌 + Wallet TG-only
